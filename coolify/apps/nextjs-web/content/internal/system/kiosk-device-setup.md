拠点フロアで使う共有タブレット（キオスク端末）の配布・登録マニュアル。管理者向け。QRカードの発行は QRカード管理（SY08）、端末の管理は 端末管理（SY09）で行う。

## 専用アプリ（APK）

タブレットには専用の Android アプリをインストールする。APK は次の URL で常に最新版が配布される。

- 本番: `https://ckk-kiosk.kai-lab.net/apk/ckk-kiosk.apk`
- 開発: `https://ckk-kiosk-dev.kai-lab.net/apk/ckk-kiosk-dev.apk`

## 新規端末の登録（QR プロビジョニング）

初期化直後のタブレットを、ケーブルや PC を使わずに専用キオスク端末として構成する。

1. タブレットを拠点出荷状態に初期化する
2. 初期設定の「ようこそ」画面を **6 回タップ**する（QR スキャナが起動する）
3. Wi-Fi に接続し、下のプロビジョニング QR をスキャンする
4. APK が自動でダウンロード・インストールされ、端末がキオスクモードにロックされる

> **プリインストールアプリ（ブロートウェア）は自動で無効化される。** この端末は業務アプリ専用なので、メーカーが最初から入れているアプリは登録時にまとめて無効化される（ランチャーに出るものが対象）。キーボード・画面表示・自動更新・メンテナンスの「設定を開く」に必要なものは残るので、操作に影響は無い。
>
> 効くのは**この手順で新しく登録した端末だけ**。すでに使っている端末を綺麗にしたい場合は、初期化してこの手順をやり直す。

## 端末のリンクと有効化（SY09）

アプリが起動したら、端末を業務システムに登録する。

1. 端末管理（SY09）で端末プロファイルを作成する
2. タブレットの画面にリンクコード（QR）が表示される（10 分間有効）
3. SY09 でそのコードをスキャンまたは入力し、プロファイルにリンクする
4. リンク済みの端末を**有効化**すると、タブレットで QR カードログインが使えるようになる

## ロックなし端末へのインストール（検証用）

キオスクロックせずに試す場合は、タブレットの Chrome で APK の URL を開き、「提供元不明のアプリ」を許可してインストールする。

## 接続インジケータ（ヘッダー右上のドット）

キオスク画面のヘッダー右上に接続状態のドットが表示される（タップで説明表示）。

- **灰**: 接続なし（サーバーに到達できない）
- **赤**: サーバーには繋がるが端末が未登録（リンクされていない）
- **橙**: 登録済みだが通常ブラウザで利用中（専用アプリのハードウェア鍵なし）
- **緑**: 専用アプリ（ハードウェア鍵）で正常に接続中
- **橙/緑の点滅**: 接続が不安定（直近に通信失敗があった）

判定はキオスク URL 自身への疎通で行うため、**インターネット接続は不要** — URL が LAN 内で解決される構成でもそのまま正しく動作する。

## オフラインモード

サーバーに到達できなくなると、Web 画面は全画面の「サーバーに接続できません」表示に切り替わり、接続が回復すると自動的に元の画面へ戻る。専用アプリ（v0.4.0 以降）はページ読み込み自体が失敗した場合もアプリ内のオフライン画面を表示し、疎通が回復した時点で自動的に再読み込みする。端末側の操作は不要。

## 画面の常時表示（時計・バッテリー・接続状態）

キオスクは全画面表示で OS のステータスバーが見えないため、アプリのヘッダー右上に**接続状態ドット・バッテリー残量・現在時刻**を常時表示する。バッテリーは充電中は緑の稲妻アイコン、残量 15% 未満は赤字になる。画面は常にダークテーマ。

## 画面スリープ（充電中はスリープしない）

- **専用アプリ**: アプリ表示中は常に画面 ON（スリープしない）
- **ブラウザ利用時**: **充電中のみ**画面をスリープさせない（バッテリー駆動時は OS の設定どおりスリープする）

## Wi-Fi（ネットワーク）を変更するには

キオスクロック中でも、管理者は一時的にロックを外して Android 設定を開ける:

1. 画面の**右上隅を 3 秒以内に 5 回タップ**する（メンテナンスダイアログが開く）
2. **管理者 PIN** を入力し「**設定を開く**」をタップ（PIN は**全端末共通・毎日 4:00 に自動更新** — 端末管理（SY09）の端末詳細「PIN・設定コード」で確認。表示は監査ログに記録される）
3. Android の設定が開くので **Wi-Fi を変更**する
4. 戻るボタン等でアプリに戻ると**自動で再ロック**される（追加操作は不要）

> 左下の 5 タップは別機能（端末設定 — 6 桁の設定コードで解錠）。ネットワーク変更は**右上**。

## PIN で開けなくなった端末を復旧する

Wi-Fi が切れた端末では、上の手順が使えなくなることがある。**端末は PIN をローカルに持っていて、オフラインの間は新しい PIN を受け取れない**ため、SY09 に出ている現在の PIN を入れても開かない。上から順に試す — 下へ行くほど手間と失う物が増える。

### 1. その端末が保持している PIN を見る

SY09 の端末詳細「PIN・設定コード」→「**この端末が保持している PIN**」の「表示」。その端末に**最後に渡した番号**が出るので、これを入れる。

「**最終同期**」が「**未同期**」の端末は、まだ一度も番号を受け取っていない。この場合サーバー側に番号は無く、端末は **APK のビルド時に埋め込んだ番号**のまま。ビルドした Mac の `~/.gradle/gradle.properties` の `KIOSK_UNLOCK_PIN`（未設定なら `246810`）を確認する。

### 2. USB でつないで Wi-Fi を直す（PIN 不要）

キオスクロックは**画面（Lock Task）を固定するだけ**で、USB デバッグは塞いでいない（アプリは `DISALLOW_DEBUGGING_FEATURES` 等の制限を一切かけない）。プロビジョニングで USB デバッグを有効にしてあれば、そのまま生きている。

```bash
~/Library/Android/sdk/platform-tools/adb devices -l
```

- `device` … そのまま次へ
- `unauthorized` … タブレット画面の「USB デバッグを許可しますか?」で「**このパソコンからのUSBデバッグを常に許可する**」→「許可」。出ないときはケーブルを挿し直す（ダイアログは接続時にしか出ない）
- 何も出ない … **充電専用ケーブル**の可能性が高い。データ転送できるケーブルに替える

つながったら PIN を使わずに Wi-Fi を直せる:

```bash
~/Library/Android/sdk/platform-tools/adb shell svc wifi enable
~/Library/Android/sdk/platform-tools/adb shell cmd wifi connect-network "SSID" wpa2 "パスワード"
~/Library/Android/sdk/platform-tools/adb shell cmd wifi status
```

オープンなネットワークは `wpa2 "パスワード"` の代わりに `open`。つながれば端末は自力で復旧する（PIN は次の同期で最新になる）。

デバッグビルドなら、端末が保持している PIN を直接読むこともできる:

```bash
~/Library/Android/sdk/platform-tools/adb shell run-as jp.co.ckk.kiosk.dev \
  cat /data/data/jp.co.ckk.kiosk.dev/shared_prefs/kiosk.xml
```

`<string name="unlock_pin">` を見る。`not debuggable` / `unknown package` はリリースビルドなので不可。`unlock_pin` の行が無ければ一度も同期していない。

### 3. 強制的に初期化する（最終手段）

> ⚠️ **これは最後の手段。急がないこと。** 初期化は取り消せず、再登録（QR プロビジョニング + SY09 でのリンク解除・再リンク）まで含めて半日仕事になる。**1 と 2 を必ず先に試す** — ケーブルを替える・PIN を 3 つ試すだけで直ることの方が多い。

#### 初期化してよいのはどんなときか

**次のすべてに当てはまるときだけ**初期化する:

- SY09 の「この端末が保持している PIN」を入れても開かない（「未同期」ならビルド時の PIN も試した）
- データ転送できるケーブル**に替えても** `adb devices` に何も出ない、または `unauthorized` のまま許可ダイアログが端末画面に出ない
- 端末が Wi-Fi に戻る見込みが無い（旧 SSID をテザリング等で再現する手も無い）

**初期化してはいけない / まだ早いとき:**

| 状況 | 先にやること |
|---|---|
| `adb devices` に `unauthorized` と出る | 端末画面の許可ダイアログを承認する（挿し直すと再表示）。USB デバッグは生きている |
| `adb devices` に何も出ない | **充電専用ケーブルを疑う。** データ転送できるケーブルへ交換 |
| 端末がまだオンライン、または戻せる | 旧 SSID を再現して自動接続させる。つながれば PIN は自動で最新化 |
| Google アカウントの有無が分からない | **確認してから。** 下の FRP を参照 |
| 単に PIN が分からないだけ | SY09 の「この端末が保持している PIN」/「履歴」を見る |

#### 先に確認すること

**この端末に Google アカウントを追加したことがあるか。** あると初期化後に FRP（Factory Reset Protection）がそのアカウントを要求し、分からなければ**端末は二度と使えなくなる**。デバイスオーナー登録はアカウント無しが条件なので通常は無いはずだが、思い込みで進めないこと。

失うのはデバイストークン・アテステーション鍵・端末に残っていた PIN だけ。セッション・操作履歴・監査ログはサーバー側にあるので消えない。

1. **USB ケーブルを抜く**（給電していると充電画面へ入ってしまう）
2. 電源を切る（長押し → 電源を切る。キオスク中でも電源メニューは使える）
3. 電源オフから **音量↑ + 電源**を約 10 秒、振動するまで長押し → ブートメニュー
4. メニューを**音量キーでスクロール**して **Recovery Mode** を探す。あれば選んで手順 6 へ

**Recovery が無く「enter meta mode」「enter fastboot mode」しか出ない場合**（MediaTek 機。TB330FU 等）:

> **META mode は選ばない** — 工場出荷時の診断モードで、用途が違う。

5. 「**enter fastboot mode**」を選び、USB でつないでから:

   ```bash
   ~/Library/Android/sdk/platform-tools/fastboot devices        # <serial> fastboot と出る
   ~/Library/Android/sdk/platform-tools/fastboot reboot recovery # 効かなければ fastboot oem reboot-recovery
   ```

   fastboot は **adb の許可ダイアログが要らない**ので、手順 2 の `unauthorized` で詰まっていても使える。

   > `fastboot -w` とブートローダーのアンロックは**使わない**。ロック状態では `-w` は失敗し、アンロックは端末を消したうえ FRP を踏む可能性がある。

6. リカバリ起動後、**倒れた Android ロボットと「No command」**が出る。これは異常ではない。**電源を押したまま音量↑を 1 回**押して離すとメニューが出る
7. **Wipe data / factory reset** を選んで実行

> ブートメニューのキー操作は機種によって違う。音量↑+電源で出ないときは**音量↓+電源**、または音量両方+電源を試す。

### 4. 初期化後の再登録

**1. アプリを入れ直す。** 上の「新規端末の登録（QR プロビジョニング）」をやり直す。初期化直後の「ようこそ」画面で**同じ場所を 6 回タップ** → QR スキャナ → Wi-Fi 接続 → QR を読む、で APK の導入とデバイスオーナー登録まで自動で終わる。ケーブルが要らないので、そもそもケーブルが原因だった場合でも確実。

**2. 端末登録画面（setup）を開く。** アプリが起動すると、端末 Cookie が無い状態なので**自動で登録画面へ移動する**（リンクコードと QR が表示される）。もし別の画面で止まっていたら、アドレスを直接開く:

| 環境 | URL |
|---|---|
| dev | `https://ckk-kiosk-dev.kai-lab.net/setup` |
| 本番 | `https://ckk-kiosk.kai-lab.net/setup` |

画面にリンクコード（12 桁）と QR が出る。**有効期限は 10 分**なので、切れたら画面を再読み込みして出し直す。

**3. SY09 側でプロファイルを開け直す。** 端末管理（SY09）で該当端末を開き「**リンク解除**」する。状態が PENDING（オープン）に戻り、**名称・拠点・フロアマップのピンは残る**（新規に作り直すとピンの置き直しが要るので、必ずリンク解除を使う）。リンクできるのは PENDING のプロファイルだけ。

**4. リンクして有効化する。** SY09 でタブレットのリンクコードを入力する（または QR をスキャン）→ LINKED になる → 「**有効化**」で ACTIVE。タブレット側はポーリングで検知し、自分でデバイストークンを発行してキオスク画面に入る。

**5. 確認する。** SY09 の端末詳細で:

- 「**最終同期**」が埋まること。埋まっていれば、この端末は以後ちゃんと PIN を受け取れている（ここが「未同期」のままなら、また同じ状況に戻る）
- 「**この端末が保持している PIN**」が現在の PIN と一致すること

再ビルドするなら、このときに `~/.gradle/gradle.properties` の `KIOSK_UNLOCK_PIN` を意図した値にしておく（既定のまま配布しない）。

## カメラ（QR スキャン）が起動しないとき

QR スキャン画面で「**カメラを起動できません。カメラ権限と HTTPS 接続を確認してください。**」が出る場合。上から順に確認する。

### まずアプリを最新にする

**専用アプリが古いと起こる。** 端末管理（SY09）の端末詳細で「プロファイル取得」が空欄・「鍵フィンガープリント」が未束縛になっていたら、その端末は **v0.6.0 より古い**アプリで動いている。

アプリは自動更新（約 1 時間ごとに確認 → 深夜に適用）なので、**配布している APK 自体が古くないか**を先に確認すること。配布物が古いままだと、端末をいくら初期化・再登録しても古いアプリが入る。

### カメラ権限

専用アプリはデバイスオーナーとして**カメラ権限を自分に付与する**ので、通常は許可を聞かれずに使える。聞かれた場合や一度「許可しない」を選んでしまった場合は、メンテナンス（右上 5 タップ → PIN →「設定を開く」）から Android 設定 → アプリ → 権限 → カメラ を「許可」に戻す。

### HTTPS で開いているか

カメラは **https でしか使えない**（ブラウザの仕様）。社内 LAN のアドレス（`*.ckk-tools.loc`）を **http** で開いているとカメラは起動しない。公開アドレス（`ckk-kiosk.kai-lab.net` / `ckk-kiosk-dev.kai-lab.net`）か、社内 CA を入れた **https** の LAN アドレスを使う。

### カメラ切替が出ないとき

カメラは映っているのに歯車（カメラ選択）が出ない場合、以前は**カメラ一覧の取得に失敗するとエラー表示になり、切替メニューも消える**不具合があった（実機 TB330FU で確認）。修正済みなので、まずアプリを最新にする。

それでも切替が出ないときは、その端末にカメラが 1 つしか無い（選ぶ相手がいない）。**歯車は 2 つ以上あるときだけ出る。**

### それでも直らないとき

他のアプリがカメラを掴んだままのことがある。端末を**再起動**して試す。再起動後も駄目なら、カメラそのものの故障を疑って別の端末と入れ替える。

## 端末の更新（自動）

アプリは**自動更新**される。約 1 時間ごとに新しいリリースを確認し、見つかると業務を妨げないよう深夜（1:00〜6:00）に自動で適用・再起動する（アプリ起動直後に見つかった場合は即時適用）。新しい APK をリリースするだけでよく、端末側の作業は不要。

- キオスクロック済み端末: 完全自動（確認ダイアログなし）
- ロックなしの検証用端末: OS のインストール確認ダイアログが表示されるので「インストール」をタップする

> 自動更新に対応する前の旧バージョン（v0.2.x 以前）が入っている端末のみ、従来どおり USB 接続で `adb install -r`、または初期化して新しい QR を再スキャンして更新する。
