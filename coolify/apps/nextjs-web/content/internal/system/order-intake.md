お客様が **order-intake@ckk-tool.co.jp** へ送った注文書を、人手を介さずに注文請書へ取り込む仕組みの運用ページです。利用者向けの操作は「[注文書取込（SY0C）](/manual/ja/operations/system/order-intake/user)」を参照してください。

> **メール取込は本番（main）に届きます。** ゲートウェイは環境ごとではなく **`common` に 1 つだけ**置いてあり、`order-intake@ckk-tool.co.jp` を巡回して**本番の**取込フォルダへ入れます。メールアドレスは環境で分けられない（ドメインもアドレスも 1 つしかない）ため、2 つ置くと同じ受信箱を取り合ってしまうからです。
>
> **検証環境（dev）にメール取込はありません。** dev で試すときは SY0C の投入か取込フォルダへ直接置いてください — メールを経由しないだけで、その先はまったく同じ経路です。

## 全体の流れ

```
お客様 ──メール──> order-intake@ckk-tool.co.jp （さくらのメールサーバー）
                         │  intake-gateway が 120 秒ごとに IMAP で巡回
                         ↓
                   取込フォルダ（INTAKE_DIR）
                         │  nextjs-web のポーラーが 60 秒ごとに走査
                         ↓
        採番 ORD- → AI 読み取り（po-extract）→ 取引先・製品の突合 → 下書き
```

**取込フォルダに落ちたあとは、共有フォルダへ人が直接置いたときと同じ経路**です。メール特有の処理は「添付を選んでフォルダに置く」までで終わります。

## 登場するもの

| 名前 | 何者か |
|---|---|
| `order-intake@ckk-tool.co.jp` | お客様が送る宛先。**自動取込専用で人は読みません** |
| `intake-gateway` | 受信箱を巡回して添付をフォルダへ置くコンテナ（Coolify 管理・**common に 1 つ**・内部専用） |
| 取込フォルダ | `intake-gateway` と `nextjs-web` が共有するサーバー上のフォルダ |
| `admintools`（SY0B 相当の管理ツール） | メールアドレスの作成・削除。さくらのコントロールパネルを自動操作します |

## どの添付が取り込まれるか

**取り込むもの** … 拡張子が **PDF / PNG / JPG / WEBP**（1 件 20MB まで）の添付。FAX 由来の TIFF は自動で PDF に変換してから取り込みます。

**取り込まないもの**

- 本文に埋め込まれた画像（**署名の会社ロゴ**など）。これを取り込むと 1 通ごとにロゴが注文請書として採番されてしまうため、意図的に外しています。
- `.p7s`（電子署名）・`.ics`（予定表）・`.txt`・`.html` など、上記以外の形式。
- 送信元が許可リスト（`INTAKE_MAIL_ALLOW_FROM`）から外れているメール。**未設定なら全部受け付けます**。

1 通に注文書が 3 通添付されていれば、**注文請書も 3 件**できます（1 通の注文書 = 1 件）。

## 取り込んだあとメールはどうなるか

| 結果 | メールの扱い |
|---|---|
| 添付を全部取り込めた | **既読**にして「**Processed**」フォルダへ移動 |
| 取り込める添付が 0（本文だけ・署名だけ） | **既読**にするだけ。受信箱に残す（人が見つけられるように） |
| 一部でも失敗した | **既読**にして「**Failed**」フォルダへ移動。**自動では再送しません** |
| 接続・認証の失敗 | 何もしない（未読のまま）。次の巡回でやり直します |

> **失敗したメールを自動で取り込み直さないのは意図的です。** 半分成功したメールをもう一度処理すると、同じ注文書が二重に登録されることが確定するためです（添付 1 件ごとの重複判定ができません）。失敗したときは、送信者に再送を依頼するか、添付を保存して注文請書の「優先取込」から上げてください。

## 確認の仕方

**取り込まれたか** … SY0C「注文書取込」の「取込待ち」に `mail_送信元_ファイル名` の形で並びます。60 秒ほどで `ORD-…` に採番され、注文請書の一覧に現れます。

**メール側** … `order-intake@ckk-tool.co.jp` の受信箱を、通常のメールソフト（IMAP: `ckk-tool.sakura.ne.jp` / 993 / SSL）で開けます。処理済みは「Processed」、失敗は「Failed」にあります。

**動いているか** … adminTools の「**メール監視**」で、未読の滞留（＝ゲートウェイが止まっている）と Failed の滞留（＝人が拾う必要がある注文書）が見られます。詳しく見るときはサーバーで `docker logs intake-gateway`。

| ログ | 意味 |
|---|---|
| `メール取込を開始します: …` | 正常に起動 |
| `未読 N 通を処理します` → `取込フォルダへ配置: …` | 取り込んでいます |
| `受理できる添付なし` | 添付が無い、または対象外の形式だけだった |
| `メール取込は無効です（… が未設定です）` | 設定が足りません（理由が出ます）。落ちずに待機します |
| `取込フォルダが使えません` | フォルダが見えない・書けない。**この状態では巡回を始めません**（注文書を取りこぼさないため） |

## 困ったとき

**メールを送ったのに取り込まれない**

1. 受信箱で、そのメールが**既読**になっているか見ます。既読なら処理は試みています。「Failed」にあれば失敗、受信箱に残っていれば「取り込める添付が無かった」ということです。
2. 未読のままなら、ゲートウェイが動いていないか、受信箱に届いていません。ログを見ます。
3. 添付の形式を確かめます（PDF・PNG・JPG・WEBP 以外は取り込みません）。

**取込待ちに並ぶが、いつまでも「未採番」のまま** … これはメール側ではなく取込フォルダ側の問題です。SY0C の「今すぐスキャン」を押し、それでも動かなければ `nextjs-web` のログを見てください。

**受信箱がいっぱいになる** … 「Processed」へ移す設定が効いていない可能性があります。ログに「メールを … へ移せませんでした（既読にはしてあります）」が出ていないか確認してください。

## 受信箱を新しく作るとき

メールアドレスの作成は **admintools** が担当します（さくらのコントロールパネルを自動操作します）。

1. admintools の「メール」画面でアカウントを追加します。**利用者名（username）** とメールアドレスは別にできます（システム用の窓口は `other-sys.` で始める運用です）。
2. **「同期」を実行**します。ここで初めてさくら側に実体が作られます。
3. 作られるのは **メールユーザー**と、必要なら **エイリアス**の 2 つです。利用者名とメールアドレスの `@` の左側が違うとき、**IMAP のログイン名になるのはメールアドレスのほう**です（`order-intake@ckk-tool.co.jp` がこの形です）。
4. できたアドレスを `intake-gateway` の設定（`INTAKE_MAIL_USER` / `INTAKE_MAIL_PASSWORD`）に入れて、再デプロイします。

> **同期の「一覧に無いものを削除」は使わないでください。** 管理表に載っていないさくら側のメールボックスが消えます。実行前に「差分を確認」で、作られる・消えるものを必ず見てください。

> **ゲートウェイを環境ごとに増やさないでください。** メールアドレスは 1 つしかないので、2 つ置くと同じ受信箱を取り合い、どちらか一方でしか取り込まれません。これが `common` に 1 つだけ置いている理由です。

## いま残っていること

1. `dev` → `main` の昇格（`coolify/apps/intake-gateway/` が `main` に無いとビルドできません）

3. Coolify UI で受信箱の資格情報を入れる
4. `./deploy.sh intake-gateway`

手順の詳細は `coolify/apps/intake-gateway/README.md` にあります。

## 記録されないこと（既知の制約）

**送信元・件名・メールの本文は、注文請書には記録されません。** 手掛かりは次の 2 つだけです。

1. ファイル名に残る `mail_送信元_` の部分（SY0C の一覧と、採番後のファイル名に残ります）
2. `intake-gateway` のログ

注文請書の詳細画面からは辿れず、「この取引先から来たメール」を検索することもできません。取り込みの仕組みを業務データから切り離しておくための割り切りです。件名や本文まで確認したいときは、受信箱を直接開いてください。
