外部システムが業務データを**読む**ための API です。口の一覧・引数・応答の形は **[リファレンス](/manual/ja/integration/reference/resources)**（コードから自動生成）にあります。このページは、リファレンスだけでは分からない**使い方の約束**をまとめています。

## 基本

- 基点の URL は `https://<ホスト>/api/v1`（検証環境は `https://app-dev.ckk-tool.co.jp/api/v1`）。
- 認証は `Authorization: Bearer <トークン>`。トークンは [API クライアント](/manual/ja/operations/system/external-api/user)（`SY0I`）で発行します。
- 疎通確認は `GET /api/v1/me`。呼び出し元の名前と**実効権限のコード**が返るので、403 の原因もここで確かめられます。
- 口の仕様そのものは `GET /api/v1/openapi.json`（要認証・OpenAPI 3.1）でも取れます。

```bash
curl -H "Authorization: Bearer $CKK_TOKEN" \
  "https://app-dev.ckk-tool.co.jp/api/v1/order-acceptances?limit=50"
```

## 一覧の読み方（keyset）

一覧は **`OFFSET` を使いません**。読んでいる最中に行が増えると、`OFFSET` は行を黙って飛ばすためです。

```json
{ "data": [ … ], "page": { "nextCursor": "…", "hasMore": true }, "syncedAt": "2026-09-10T04:11:52.881Z" }
```

- `page.hasMore` が `true` の間、`page.nextCursor` を `?cursor=` に渡して読み進めます。
- カーソルは**中身を解釈しないでください**（形は予告なく変わります）。壊れたカーソルは黙って先頭に戻らず `400` になります。
- 1 ページの件数は `?limit=`（上限あり）。

## 差分取得（`updatedSince`）

初回は全件を読み、**応答の `syncedAt` を保存**します。次回からは `?updatedSince=<保存した syncedAt>` を付けて、変わった行だけを読みます。

- `syncedAt` は**このシステムの DB の時計**です。**自分の時計から作らないでください**（時計がずれた分の行が永久に抜けます）。
- 境界は**含みます**。同じ行が 2 回届くことがあるので、**処理は冪等**に作ってください。
- 在庫取引（`/inventory/transactions`）だけは更新されない台帳なので、作成時刻で絞ります。

## 削除は別の口

行の物理削除は `updatedSince` では**見えません**。`GET /api/v1/deletions?sinceEventId=<前回の lastEventId>` も合わせて読みます。ほとんどの書類は削除ではなく状態で表すので、ここに出るのは主に下書きの出荷書です。psql などで直接消した行は観測できません（復旧作業をしたときは全件を取り直してください）。

## 値の形

- 書類番号（`number`）は画面・印刷物と同じ `ORD-2026-00042` の形です。**番号だけでは書類が 1 つに決まりません** — 連番は発行会社（自社法人）ごと・会計年度ごとなので、同じ番号が別の会社にもあり得ます。突き合わせ・保存には `id`（行の uuid）か、`companyCode` + `number` の組を使ってください。
- 以前の形の番号（`ORD-202609-00042`）で作られた書類は振り直してあり、もとの番号は `legacyNumber` に入っています。番号の決まりは[書類番号のルール](/manual/ja/start#doc-number)を参照してください。
- 状態は DB の値そのまま（`CONFIRMED`）。日本語のラベルは返しません。
- 多言語の列は `{ "ja": "…", "en": "…" }`。金額は数値で、通貨は別項目。日時は UTC の RFC 3339。
- **未知の値が増えることがあります**（例: 注文種別の `REGRIND`）。`switch` には必ず既定の枝を置いてください。

## エラー

誤りは RFC 9457（`application/problem+json`）です。`code` で分岐してください（文面は変わりえます）。

- 認証に失敗したときは**理由によらず同じ 401** です（トークンが存在するかを外から探れないようにするため）。理由は管理側のログにだけ残ります。
- 403 は「トークンは正しいが権限が足りない」。本文に必要な権限（例: `quote:READ`）が入ります。
- 429 は認証失敗が続いた送信元への制限です。

## 行スコープ

API は画面と**同じ規則**で行を絞ります。たとえば作成者でスコープされた権限なら、他の人が作った見積書は返りません。見えるはずの行が見えないときは、API クライアントに付けたロールの範囲を確かめてください。
