在庫が動いた **1 回ぶんの出来事** が 1 枚の伝票になります。「この製品はいつ・何本・どこへ動いたのか」を後から追うためのアプリです。操作コードは `ST04` です。

> ⚠️ このアプリは今のところ **テスト用の環境だけ** で使えます。本番で使えるようになるまでに、画面や手順が変わることがあります。

> このアプリが属するフロー … [生産の流れ](/manual/ja/process/production)

## このアプリでできること

- 在庫が動いた記録を、伝票の単位で一覧できます。
- 何がきっかけで動いたか（事由）と、元になった書類を確認できます。
- 1 枚の伝票の中で、どの品目がどの棚から何本動いたかを確認できます。
- 数が合わないときに「いつ動いたのか」をさかのぼるために使います。

> ⚠️ 伝票は **後から直せません**。作り直しも取り消しもできない記録です。間違っていたときは、逆向きの入出庫を[手動入出庫](/manual/ja/operations/inventory/goods-movement/user)で新しく登録します。

## 用語（このページで出てくる言葉）

- **伝票番号** … `MOV-` で始まる番号です。月ごとに 1 番から振り直します。
- **事由（じゆう）** … 何がきっかけで在庫が動いたかです。
- **元書類** … その動きを起こした書類（指示書・出荷書など）です。
- **明細** … その伝票の中の 1 行です。「この棚から 5 本出た」の 1 件にあたります。

## 在庫が動くと、必ず伝票ができます

在庫の数は、この画面からではなく日々の操作にあわせて動きます。そのすべてに伝票が 1 枚付きます。

| 事由 | どんなときにできるか |
|---|---|
| 指示書完了 | 指示書のすべての工程が終わり、できあがりが在庫に入ったとき |
| 出荷 | 出荷書で出荷したとき |
| 素材入荷 | 素材が入荷したとき |
| 在庫移動 | 在庫の置き場所を変えたとき |
| 引当予約 / 予約解除 | 注文のために取り置きしたとき・外したとき |
| 棚卸調整 | 棚卸を確定して、数え直した結果を反映したとき |
| 手動入出庫 | 人が[手動入出庫](/manual/ja/operations/inventory/goods-movement/user)から登録したとき |
| 外注へ出し / 外注から戻り | 工程の外注で、品物を預けたとき・戻ったとき |
| 返品 | 出荷したあとの返品を記録したとき |
| 不明（移行前） | この仕組みができる前の古い記録に、後から付けた伝票です |

> 💡 1 回の出来事 = 1 枚です。たとえば指示書の完了では、できあがりの入庫・半製品の入庫・使った素材の出庫が **同じ 1 枚** の明細として並びます。

## 一覧の見かた

- **伝票番号** … `MOV-YYYYMM-NNNNN` の形です。押すと詳細が開きます。
- **日時** … 伝票ができた日時です。
- **事由** … 色つきのバッジで出ます。
- **拠点** … その動きが起きた拠点です。拠点をまたぐ移動では空欄になります。
- **明細数** … その伝票に入っている行数です。
- **元書類** … 指示書番号・出荷書番号などです。押すとその書類が開きます。

絞り込みは「伝票番号での検索」「事由」「拠点」の 3 つです。

> ⚠️ 一覧に出るのは **直近 1000 件** です。それより古い伝票は絞り込んでも出てきません（「直近 1000 件のみ表示しています」と出ます）。古いものを探すときは、元の書類の画面からたどってください。

## 詳細の見かた

上に伝票そのものの情報（番号・日時・事由・拠点・元書類・登録者・備考）が出ます。下の表が明細です。

- **品目** … 動いた品物です。
- **区分** … 「入庫」「出庫」「予約」「予約解除」「棚卸調整」のどれかです。
- **数量** … 動いた本数です。
- **保管場所・棚** … どこから・どこへかです。
- **ロット** … 製品のロット番号です。
- **備考** … その行がなぜ起きたかの説明です（「指示書 #1024 完成入庫」など）。

## よくある質問・困ったとき

**Q. 番号が飛んでいます。**
A. 正常です。番号は先に取るので、登録が途中で失敗すると、その番号は使われないまま飛びます。

**Q. 間違って登録した入出庫を消したいです。**
A. 消せません。**逆向きの入出庫を新しく登録** して打ち消します（[手動入出庫](/manual/ja/operations/inventory/goods-movement/user)）。記録として両方が残ります。

**Q. 事由が「不明（移行前）」になっています。**
A. この仕組みができる前の記録です。当時は「何が起きたか」を残していなかったので、後から分からないものはこの事由になっています。

**Q. 出荷したのに「出庫」の行がありません。**
A. 出荷書の種別が「**在庫保管**」のときは、社外へ出るのではなく保管の拠点へ **入る** 動きになります。事由は「出荷」のまま、明細は「入庫」です。

## 必要な権限

この画面を使うには **在庫**（`inventory`）の権限が要ります。

| したいこと | 必要な権限 |
| --- | --- |
| 画面を開く・一覧や詳細を見る | 在庫 の 閲覧 |
| 追加・変更・削除する | 在庫 の 作成 / 更新 / 削除 |

見るだけなら「閲覧」で足ります。追加・変更・削除の操作がある画面では、その操作にあたる権限がそれぞれ必要です。

権限は役割（ロール）を通して付きます。足りないときは管理者に相談してください。

権限の全体像は「[権限とロール](../../../permissions)」を参照してください。
