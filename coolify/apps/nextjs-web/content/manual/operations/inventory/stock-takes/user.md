拠点・保管場所ごとに **実物を数え直し**、帳簿の数と食い違っていれば直すアプリです。操作コードは `ST05` です。

> ⚠️ このアプリは今のところ **テスト用の環境だけ** で使えます。本番で使えるようになるまでに、画面や手順が変わることがあります。

> このアプリが属するフロー … [生産の流れ](/manual/ja/process/production)

## このアプリでできること

- 拠点（と、必要なら保管場所）を選ぶだけで、そこにある在庫のすべてが数える対象として自動で入ります。
- 数えた結果を記入し、帳簿の数との差異をその場で確認できます。
- 承認設定（MS0B）にフローがあれば承認を経て、無ければそのまま確定します。
- 確定すると、差異のある品目だけ [入出庫伝票](/manual/ja/operations/inventory/inventory-movements/user)（ST04）の「棚卸調整」として自動で反映されます。差異が無かった品目には何も起きません。

> 💡 在庫が**マイナス**になっているとき（在庫不足のまま出荷した分）も、棚卸で数え直せば 0 以上に戻ります。

## 用語（このページで出てくる言葉）

- **棚卸（たなおろし）** … 実物を数えて、帳簿の在庫数と合っているか確かめる作業です。
- **帳簿数** … 棚卸を始めた時点で、システムに記録されていた数量です。
- **記入数** … 実際に数えた数量です。
- **差異** … 記入数から帳簿数を引いた数です。ここでは記入した時点の目安で、実際に反映されるのは確定時点の数との差です（下の「確定すると何が起きるか」を参照）。
- **下書き / 記入中 / 確定 / キャンセル** … 棚卸そのものの状態です。
- **承認依頼中 / 承認済 / 差し戻し** … 承認が必要なときの状態です。

## 棚卸をはじめる

1. 一覧の「**新規作成**」を押します。
2. 「**拠点**」を選びます（必須）。
3. 数える範囲を保管場所 1 つに絞りたいときは「**保管場所**」も選びます（任意。空のままだとその拠点全体が対象になります）。
4. 必要なら「**備考**」を書きます。
5. 「**作成**」を押します。

作成すると、その時点でその拠点（・保管場所）にある在庫の **すべてのバケット** が、数える対象として自動で行に入ります。**在庫数が 0 の場所や、置き場所が未割当の在庫も含まれます** — 「あるはずの場所に実物が無かった」「無いはずの場所に実物があった」の両方を見つけられるようにするためです。対象がまったく無いとき（その拠点に在庫が何も無いとき）は作成できません。

## 記入する

詳細画面の記入グリッドで、実際に数えた数を入れていきます。

- **種別** … 製品か素材かのバッジです。
- **品目名** … 数える対象の品目です。
- **保管場所** … その在庫の置き場所です。
- **ロット** … 製品の場合のロット番号です。
- **帳簿数** … 棚卸を始めた時点の記録上の数です（直せません）。
- **記入数** … 実際に数えた数を入れます。
- **差異** … 記入数と帳簿数の差です。多いと青、少ないと橙、まだ数えていない行は「**未カウント**」と出ます。
- **備考** … その行への補足です。

上に「◯ / ◯ 件カウント済み」「差異 ◯ 件」などの要約が出ます。

「**保存**」を押すと、そこまでの記入が残ります。**最初の保存で、棚卸の状態が「下書き」から「記入中」に変わります。** 保存は何度でもできるので、1 回で数え切らなくても大丈夫です。

## 提出する

1 行でも記入したら「**提出**」を押せます。

- 承認設定（MS0B）の「棚卸」フローに段が **1 つ以上あれば**、承認依頼になります。棚卸の状態は「記入中」のまま、承認状態が「**承認依頼中**」になります。
- 段が **1 つも無ければ**、提出した時点でそのまま確定します。

提出後、承認待ちの間も記入をやめることはできません（承認依頼中は記入グリッドが編集不可になります）。

## 承認する

承認する権限がある人は、詳細画面の上部にあるカードから「**承認**」または「**差し戻し**」ができます。差し戻すと提出前の状態に戻り、記入し直して再提出できます。すべての段の承認が済むと、確定に進みます。

## 確定すると何が起きるか

確定のタイミングで、**その場でもう一度実物の場所ごとの数を最新の値で読み直します**（棚卸を始めてから確定までの間に、出荷や入荷で数が動くことがあるためです）。差異は「記入した数」と「その最新の数」の差で決まります。

- 差異が無い行 … 何も起きません。
- 差異がある行 … その品目・その場所ぶんの [入出庫伝票](/manual/ja/operations/inventory/inventory-movements/user)（ST04、事由「棚卸調整」）が起き、在庫の数がその差異ぶん直されます。
- 差異のある行が 1 つも無かったとき … 伝票そのものが作られません（直すものが無かった、という意味です）。
- 数えなかった行、棚卸を始めたあとに在庫そのものが無くなった場所は、確定の対象から外れます。

確定すると、詳細画面の上に、実際にできた伝票へのリンクが出ます（伝票ができなかったときは出ません）。

## キャンセルする

「下書き」または「記入中」のあいだは、詳細画面から「**キャンセル**」できます。承認依頼中にキャンセルすると、その依頼も一緒に取り消され、[未処理一覧](/manual/ja/operations/general/my-tasks/user)（CM01）から消えます。

**確定した棚卸はキャンセルできません。** 確定は在庫の数を実際に直す操作なので、取り消すには逆方向の棚卸（もう一度数えて戻す）が必要になります。

## 一覧の見かた

- **棚卸番号** … クリックすると詳細画面が開きます。
- **拠点 / 保管場所** … 対象の場所です。
- **明細数** … 数える対象の行数です。
- **状態** … 下書き / 記入中 / 確定 / キャンセルです。
- **承認状態** … 承認が要らない棚卸では「—」（ダッシュ）です。
- **更新日** … 最後に何か変わった日です。

検索欄と「**状態**」で絞り込めます。

このアプリを使うには、在庫の権限が必要です。

## よくある質問・困ったとき

**Q. 数えたのに、その品目が対象に入っていません。**
A. 棚卸を作成した時点で在庫が無かった場所は対象に入りません。あとから対象を追加することはできないので、その分は新しい棚卸を作り直してください。

**Q. 提出したのに記入グリッドが直せなくなりました。**
A. 承認依頼中は記入できません。差し戻されるか、承認設定にフローが無く自動で確定した場合は、その時点でもう記入は終わっています。

**Q. 確定したのに伝票ができていません。**
A. 差異が無かった（数えた数と、確定時点の実際の数が一致していた）ということです。正しい状態なので、何もする必要はありません。

**Q. 記入した差異と、確定後に実際に直った数が違います。**
A. 確定は「記入した時点」ではなく「**確定した時点**」の実際の数と比べます。棚卸の途中で出荷や入荷があると、記入時点の差異と確定時点の差異はずれることがあります。

**Q. 確定した棚卸を取り消したいのですが。**
A. できません。逆方向の数を数え直す新しい棚卸を作成してください。

**Q. キャンセルしたら承認依頼はどうなりますか。**
A. 承認依頼中にキャンセルすると、その依頼も一緒に取り消されます。承認する人の[未処理一覧](/manual/ja/operations/general/my-tasks/user)（CM01）からも消えます。

## 必要な権限

この画面を使うには **在庫**（`inventory`）の権限が要ります。

| したいこと | 必要な権限 |
| --- | --- |
| 画面を開く・一覧や詳細を見る | 在庫 の 閲覧 |
| 追加・変更・削除する | 在庫 の 作成 / 更新 / 削除 |

見るだけなら「閲覧」で足ります。追加・変更・削除の操作がある画面では、その操作にあたる権限がそれぞれ必要です。

権限は役割（ロール）を通して付きます。足りないときは管理者に相談してください。

権限の全体像は「[権限とロール](../../../permissions)」を参照してください。
