用来查看随发货产品一起送达的 **送货单**（納品書，出货单确定时自动生成，**生成时即为已发行**）。操作代码是 `SH02`。

> ⚠️ 本应用还在准备中。正式启用之前，界面和步骤可能会有变化。

## 本应用能做什么

- 可以查看送货单并转成 PDF。**在本界面不能编辑内容** —— 送货单由出货单和订单确认书生成，生成时就已经发行。
- **不需要自己创建送货单** —— 只要**确定**[出货单](/manual/zh/operations/shipping/delivery-order/user)，就会自动生成。直送最终用户会**同时生成两份**：一份无价格（给最终用户）、一份含价格（给客户）。
- **写上 / 不写上** 金额由订单确认书的配送方式决定（直送最终用户会生成无价格和含价格各一份）。
- 可以把送货单转成 **PDF**，打印出来或随货附上。
- 可以记录「已送达」。

## 本页出现的词

- **出荷書（出货单）** … 记录发了什么、发了多少的单据。确定它时会自动生成送货单。
- **納品先（送货对象）** … 送货单的收件人。普通送货是客户；直送最终用户的无价格那份是最终需求方。
- **通常納品 / ユーザー直送（普通送货 / 直送最终需求方）** … 「通常納品」是送到下订单的客户处，「ユーザー直送」是直接送到实际使用产品的公司。
- **最終需要家（最终需求方）** … 实际使用产品的公司。直送时的收货方就是它。
- **価格記載（记载价格）** … 送货单上是否写出单价和金额的设置。

## 界面怎么看

打开应用后，会看到之前做过的送货单一览。

![送货单一览界面](../../../assets/screenshots/delivery-note-list-01.png)

- **納品番号（送货单号）** … 以 `DRN-` 开头的编号，由系统自动编。
- **方法（方式）** … 橙色的「ユーザー直送」（直送最终需求方）是直接送到使用产品的公司，灰色的「通常納品」（普通送货）是送到客户处。
- **状態（状态）** … 蓝色是「発行済」（已发行），绿色是「納品済」（已送达）。自动生成的送货单一开始就是「已发行」。
- 上面的搜索框里可以输入送货单号、出货单号、送货对象或最终需求方的名称来筛选。
- 一览里显示的是 **从自己所属据点发出的送货单** 和 **自己做的送货单**。
- 点一行就能打开这张送货单的详细界面。

## 送货单是怎么生成的

不需要手动创建。只要**确定**[出货单](/manual/zh/operations/shipping/delivery-order/user)，就会用它的明细自动生成。

- **普通送货** … 生成 **一份** 含价格的送货单，给客户。
- **直送最终需求方** … **同时生成两份**。无价格的一份给最终需求方（实际使用产品的公司），含价格的一份给客户。**切勿把含价格的那份交给最终需求方** —— 打开或打印前，本界面会提示警告。

刚生成的送货单就已经是「**発行済**」（已发行）。没有草稿阶段，**之后不能再修改内容** —— 内容从出货单和订单确认书继承而来，请在确定出货单之前确认（确定画面会预告生成几份、给谁、是否记载价格）。也可以从出货单界面的「**納品書**」（送货单）标签页打开。

## 想修改内容时

送货单的内容（送货方式、最终需求方、记载价格、数量、单价）由出货单和订单确认书自动决定，**在送货单界面不能修改**。

- 想改送货对象或是否记载价格时，请在确定出货单**之前**，修改作为来源的[订单确认书](/manual/zh/operations/sales/order-acceptance/user)的配送方式・最终用户。
- 确定之后才发现错误时，需要从正确的订单确认书 / 出货单重新生成 —— 请联系管理员。

直送最终需求方时生成的无价格送货单，**界面上和 PDF 里都不会出现金额**。

![不写金额的送货单](../../../assets/screenshots/delivery-note-detail-noprice-01.png)

## 送到之后标记为已送达

送货单按「発行済」（已发行）→「納品済」（已送达）推进。生成时就已经发行，所以**没有发行操作**。操作在界面右上角的「**…**」（三个点的按钮）里进行。

1. 点右上角的「**…**」。
2. 选「**納品済みにする**」（标记为已送达）。
3. 弹出「納品の確認」（送达确认）后，点「**納品済みにする**」（标记为已送达）。

当天的日期会记为 **納品日（送达日）**，状态变成「**納品済**」（已送达）。

另外，这张送货单的编号，之后会作为「由来」（来源）显示在[发票](/manual/zh/operations/billing/invoice/user)的明细里。从发票可以马上打开这张送货单。

## 打印（PDF）

送货单生成后马上就能看到 PDF。

- 可以在「**PDF**」标签页里直接在画面中查看 PDF。想重新生成时点「**再生成**」（重新生成）。
- 从画面右上角的「**…**」（三个点的按钮）选择「**PDFをダウンロード**」（下载 PDF），可以保存为文件。打印请从这里进行。

![送货单详细界面](../../../assets/screenshots/delivery-note-detail-01.png)

> ⚠️ 送货单没有删除操作。做出来的送货单删不掉也改不了，所以请在 **确定出货单之前** 仔细确认预告的份数、收件人和是否记载价格。

## 输入项

送货单画面显示的项目一览。全部从出货单和订单确认书继承，在本画面不能修改。应用中项目旁边的 **?** 也可直接跳转到对应说明。

| 项目 | 必填 | 填什么 |

| [送达方](#field-recipient) | 必填 | 送货单的抬头 |
| [最终需求方](#field-end-user) | 选填 | 直送时的收货方 |
| [营业负责人](#field-sales-rep) | 选填 | 这张送货单的营业负责人 |
| [记载价格](#field-include-price) | — | 是否记载单价与金额 |
| [备注](#field-notes) | 选填 | 送货单的补充 |
| [产品](#field-product) | 必填 | 交付的产品 |
| [数量](#field-quantity) | 必填 | 交付的数量 |
| [单价](#field-unit-price) | 选填 | 送货单上记载的单价 |

### 发货单 [#field-delivery-order]

作为依据的发货单。仅供查看，不能更改。本单的产品与数量来自该发货单的明细。

### 交付方式 [#field-delivery-method]

- **通常** … 交付给受订客户，送货单随货附带
- **直送最终需求方** … 直接送交最终需求方。**送货单另行寄送**，通常不记载价格

由发货单对应的订单回执上登记的配送方式自动决定。草稿阶段可以修改。

### 送达方 [#field-recipient]

送货单的抬头。仅供查看，不能更改。普通送货是受订客户；直送最终需求方的无价格那份是最终需求方。

### 最终需求方 [#field-end-user]

直送时的实际收货方。仅大客户会被登记。由发货单的订单明细自动决定（订单明细上有指定就用它，没有则用订单回执上登记的公司）。草稿阶段可以重新选择。

### 营业负责人 [#field-sales-rep]

这张送货单的营业负责人。发货单的营业负责人能定为一人时填入那个人，定不下来时填入送达方的主负责人。需要时可以重新选择。

### 记载价格 [#field-include-price]

是否在送货单上记载单价与金额。**直送最终需求方时通常取消**（避免让最终需求方看到交易价格）。

### 备注 [#field-notes]

送货单上的补充说明。**会显示在送货单 PDF 上**，因此请不要写不想让客户看到的内容。

### 产品 [#field-product]

交付的产品。由发货单沿用。

### 数量 [#field-quantity]

交付的数量。系统会预填出货单的数量。分批交货时，请改为实际交付的数量。

### 单价 [#field-unit-price]

送货单上记载的单价。取消「记载价格」时不会打印。

## 常见问题与困扰

**Q. 确定了出货单，却没有生成送货单。**
A. 只有「发送」类的出货单才会生成送货单。「库存保管」不进入请款流程，不会生成送货单。如果是发送类却仍未生成，请联系管理员。

**Q. 想把送货对象改成别的公司，却选不了。**
A. 送货对象是根据出货单表头的客户自动决定的，在这个界面改不了。收货方不对时，需要从正确的订单回执 / 出货单重新生成。

**Q. 含价格和不含价格的送货单，该交哪一张？**
A. 直送最终需求方时会生成两份。无价格的交给最终需求方，含价格的交给客户。普通送货只生成含价格的一份。

**Q. 送货单的内容有错。**
A. 送货单之后不能修改，也没有撤销发行的操作。需要从正确的订单确认书 / 出货单重新生成，请联系管理员。弄错的那张不要交给客户。
