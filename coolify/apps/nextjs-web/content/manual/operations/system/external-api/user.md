社外のシステムが `/api/v1` を通じて業務データを**機械的に読む**ための資格情報 — **API クライアント** — を作成・管理するアプリです。操作コードは `SY0I` です。

このアプリで作れるのは「身元」だけです。そのクライアントが**何を読めるか**は、[ユーザー管理](/manual/ja/operations/system/user-management/user)（`SY01`）でロールを割り当てて決めます。身元を作る操作と、読める範囲を決める操作を分けているので、どちらも別々に確認できます。

> ⚠️ この機能はいまのところ **検証環境（dev）でのみ** 使えます。本番環境（main）に出すには別途の対応が必要です。

## このアプリでできること

- API クライアントを作成できます（作成した時点では**無効**で、トークンもありません）。
- クライアントに **トークン**（接続に使う鍵）を発行できます。生の値が見られるのは発行した直後の一度きりです。
- クライアントを **有効化** して、実際に接続できる状態にできます。
- 使わなくなったトークンを **失効** させたり、クライアントそのものを **無効化** したりできます。
- 許可する **IP 範囲** を、クライアントの作成時に設定できます。
- 各クライアントの **最終利用日時**・**有効なトークンの本数**・**割り当てられているロール** を確認できます。

## 用語（このページで出てくる言葉）

- **API クライアント** … 社外のシステムがこのシステムへ接続するための身元です。人ではなく、機械（外部システム）のためのアカウントです。
- **トークン** … クライアントが接続するときに提示する鍵（文字の並び）です。この値そのものが認証情報です。
- **許可 IP 範囲** … そのクライアントからの接続を受け付ける、送信元 IP アドレスの範囲です。空欄なら制限しません。
- **ロール** … クライアントが読める業務データの範囲を決める割り当てです。ユーザー管理（`SY01`）で、社員に付けるのと同じ方法で付けます。

## はじめる前に

- このアプリを使うには **外部 API クライアントの管理** の権限（`api_client`）が必要です。開けない場合は、システム管理者にご相談ください。
- クライアントを **有効化** することと、**トークンを発行** することは、それぞれ別に [特権アクセス](/manual/ja/operations/system/privileged-access/user)（`SY0G`）の承認が要ります。権限を持っているだけでは押せません。
- 作っただけのクライアントは、何も読めません。有効化・トークンの発行・ロールの割り当ての **3 つが揃って** はじめて、外部システムから業務データを読めるようになります。

## 開き方

ホーム画面の「**システム**」の中にある **API クライアント** を押します。または、画面上の検索欄に `SY0I` と入れます。

## 画面の見かた

アプリを開くと、登録済みのクライアントが一覧で並びます。

- **名前** … クライアントの名前と、背後にあるユーザー名（システムアカウント）です。
- **状態** … **失効済み**（赤）/ **有効**（緑）/ **無効**（灰色）の 3 つです。作成直後は「無効」です。
- **ロール** … 割り当てられているロールです。1 つも無いときは「**ロール未割当**」とオレンジで表示され、そのクライアントは何も読めません。
- **トークン** … 有効なトークンの本数です。「**1 / 2**」のように、上限（2 本）に対して何本使っているかが出ます。
- **最終利用** … 最後にこのクライアントで接続があった日時です。まだ一度も使われていなければ「**未使用**」です。

一覧の右側には、クライアントごとに「**トークンを発行**」「**有効化 / 無効化**」のボタンが並びます。

発行済みのトークンがあるクライアントが 1 つでもあると、その下に **トークンの一覧** が別枠で表示されます。トークンの値そのものは出ません（下 4 桁だけを `••••••ab3x` のように表示します）。

## クライアントを作成する

1. 画面右上の「**新規作成**」を押します。
2. 「**名前**」を入れます（必須）。
3. 「**説明**」に、用途など分かる内容を書きます（任意）。
4. 「**許可 IP 範囲**」に、接続を許可する IP をカンマ区切りの CIDR で入れます（例: `10.0.0.0/8, 203.0.113.0/24`）。空欄なら制限しません。
5. 「**保存**」を押します。

作成した時点では「**無効**」で、トークンもありません。有効化とトークンの発行は、それぞれ別に承認が要ります。

> 💡 許可 IP 範囲は、いまのところ **作成のときにしか設定できません**。あとで変更したいときはシステム管理者にご相談ください。

## クライアントを有効化する

クライアントが「無効」のままでは、トークンを持っていても外部システムから接続できません。

1. 先に [特権アクセス](/manual/ja/operations/system/privileged-access/user)（`SY0G`）で「**API クライアントの有効化**」を申請し、承認を受けます。
2. 一覧で対象のクライアントの「**有効化**」を押します。

承認を受けていない間、この「有効化」ボタンは押せません（グレーアウトしています）。承認された期間の中で最初に押した瞬間から、決められた時間だけ使えるようになります（詳しくは [特権アクセス](/manual/ja/operations/system/privileged-access/user)のページを参照してください）。

使わなくなったクライアントを止めるときの「**無効化**」には、承認は要りません。だれでもすぐに止められます。

## トークンを発行する

トークンは、クライアントが実際に接続するときに提示する鍵です。

1. 先に [特権アクセス](/manual/ja/operations/system/privileged-access/user)（`SY0G`）で「**API トークンの発行**」を申請し、承認を受けます。
2. 一覧で対象のクライアントの「**トークンを発行**」を押します。

承認を受けていない間、この「トークンを発行」ボタンは押せません。

> ⚠️ 発行すると、生のトークンの値が画面に **一度だけ** 表示されます。この画面を閉じると、二度と表示されません（データベースにも生の値は残しません）。**その場で必ず控えてください。**

控え忘れた場合は、控え直すことはできません。そのトークンを下の「**トークンを失効させる**」の手順で失効させ、あらためて発行し直してください。

**1 クライアントにつき、有効なトークンは 2 本まで** です。差し替えのときに無停止で入れ替えられるようにするための上限で、3 本目を発行しようとすると「**有効なトークンは 2 本までです。先にどれかを失効してください。**」と表示されます。

## トークンを失効させる

1. 画面下の「**トークン**」の一覧で、失効させたいトークンの行を見つけます（下 4 桁で見分けます）。
2. 「**失効**」を押します。

失効に承認は要りません。だれでもすぐに行えます。失効したトークンは、二度と接続に使えません。

## ロールを割り当てる

クライアントが実際に何を読めるかは、このアプリではなく [ユーザー管理](/manual/ja/operations/system/user-management/user)（`SY01`）で決めます。

1. ユーザー管理を開き、クライアントの背後にあるユーザー（一覧の「名前」欄に出ている、クライアントと同じ名前のユーザー）を探します。
2. 社員に付けるのと同じ方法で、ロールを付けます。

ロールを 1 つも付けていないクライアントは、有効化してトークンを発行していても、業務データを一切読めません。

## よくある質問・困ったとき

**Q. 「有効化」「トークンを発行」ボタンが押せません。**
A. その操作の承認をまだ受けていません。[特権アクセス](/manual/ja/operations/system/privileged-access/user)（`SY0G`）から、それぞれ「API クライアントの有効化」「API トークンの発行」を申請してください。

**Q. 押した瞬間に「この操作には承認が必要です」と出ました。**
A. 画面を開いたときは承認済みに見えても、実行の直前にもう一度確認しているため、その間に承認の期限が切れたか、まだ一度も使っていない申請の期間そのものが終わっていた可能性があります。[特権アクセス](/manual/ja/operations/system/privileged-access/user)の「自分の申請」で状態を確認してください。

**Q. トークンの値を控え忘れました。**
A. 再表示はできません。そのトークンを失効させ、あらためて発行し直してください。

**Q. 有効なトークンが 2 本で発行できません。**
A. 上限は 1 クライアントにつき 2 本です。使っていない古いトークンを先に失効させてから、発行し直してください。

**Q. クライアントを有効化してトークンも発行したのに、外部システムから読めません。**
A. ロールが割り当てられているか確認してください。「**ロール未割当**」のクライアントは、身元があっても何も読めません。[ユーザー管理](/manual/ja/operations/system/user-management/user)でロールを付けてください。許可 IP 範囲を設定している場合は、接続元の IP がその範囲に入っているかも確認してください。

**Q. 許可 IP 範囲をあとから変えたいです。**
A. いまの画面では作成のときにしか設定できません。システム管理者にご相談ください。

## 必要な権限

この画面を使うには **外部 API クライアントの管理**（`api_client`）の権限が要ります。

| したいこと | 必要な権限 |
| --- | --- |
| 画面を開く・一覧や詳細を見る | 外部 API クライアントの管理 の 閲覧 |
| 追加・変更・削除する | 外部 API クライアントの管理 の 作成 / 更新 / 削除 |

見るだけなら「閲覧」で足ります。追加・変更・削除の操作がある画面では、その操作にあたる権限がそれぞれ必要です。

### 承認が要る操作

次の操作は権限を持っているだけでは行えません。**特権アクセス（SY0G）で申請し、別の人の承認を受けた期間だけ**行えます。

| 操作 | 必要な権限 | 何ができるようになるか |
| --- | --- | --- |
| API トークンの発行 | 外部 API クライアントの管理（`api_client`）— 作成 | 社外のシステムが業務データを読むための鍵を刷る。刷った値がそのまま資格情報で、割り当てたロールの範囲を持ち出せる |
| API クライアントの有効化 | 外部 API クライアントの管理（`api_client`）— 更新 | 作っただけでは何も通らないクライアントを、実際に業務データを読める状態にする |

権限は役割（ロール）を通して付きます。足りないときは管理者に相談してください。

権限の全体像は「[権限とロール](../../../permissions)」を参照してください。
