这是一个可以集中查询「**谁、什么时候、从哪里、用哪台设备登录**」以及**没有成功的尝试**的应用。操作代码是 `SY0D`。

从电脑（Web）的登录和从现场共享平板（自助终端）的登录，会显示在同一个画面里。

这是只能查看的应用。无法从这个画面修改或删除记录。

## 这个应用能做什么

- 可以按时间从新到旧查看登录的**成功和失败两种记录**。
- 可以察觉「同一个人反复失败」「从不认识的地方在尝试」这类动向。
- 选择一条记录，可以详细确认当时的**连接来源和设备信息**。
- 可以按 IP 地址的范围（例如整个公司内网）筛选。

## 用语（本页出现的词）

- **尝试** … 指一次登录的动作。无论成功还是失败，都记为一条。
- **IP 地址** … 表示连接来源的号码。可以作为判断从公司内部还是外部连接的线索。
- **设备签名** … 收集浏览器特征生成的标记。这是**用于判断「是不是平时那台电脑」的参考**，并不能确定具体是哪台设备。
- **设备类别** … 自动判定该设备是否属于公司。下一节详细说明。

## 开始之前

- 打开这个应用需要**系统管理权限**。如果打不开，请与系统管理员联系。
- 记录中包含连接来源和电脑配置等信息。它们是**在需要时用于调查的**，不是用来日常观察他人行为的。
- 记录会自动删除。**成功保留 180 天，失败保留 400 天**。

## 打开方法

在主页的「システム（系统）」中点击 **ログイン履歴（登录历史）**。或者在画面上方的搜索框中输入 `SY0D`。

## 设备类别（是否公司设备）

列表和详情中会显示「**端末区分（设备类别）**」。这是系统自动判定的结果，**确定程度分为 4 级**。把鼠标移到标签上会显示判定理由。

| 显示 | 含义 | 确定程度 |
|------|------|----------|
| **会社（管理端末）** 公司（受管设备） | 通过设备内保存的密钥签名确认 | 确凿 |
| **会社（社内NW）** 公司（内网） | 连接来源在公司内网范围内 | 情况推测 |
| **未管理** 未受管 | 没有属于公司设备的证据 | 并非断定 |
| **未判定** 未判定 | 没有可判断的材料 | — |

最重要的注意点：

> ⚠️ 「**公司（内网）**」的意思是「**正在从公司内部连接**」，而**不是**「**这是公司配发的设备**」。把私人电脑带进公司，或通过 VPN 连接，显示都是一样的。
>
> 能够明确说是「公司设备」的只有「**公司（受管设备）**」。当装有专用应用的现场共享平板用保存在设备内的密钥签名申报时，才会显示这一项。

这个判定只用于显示。**不会因为这个判定而拒绝登录。**

## 画面的看法

打开应用后，上方是最近 24 小时的汇总，下方是记录列表。

### 上方汇总

- **24時間の失敗** … 失败尝试的件数。比平时多时，请查看下面的列表。
- **24時間の成功** … 成功的件数。
- **失敗の多い IP（24h）** … 失败集中的连接来源。
- **失敗の多い相手（24h）** … 失败集中的用户。用不存在的用户名尝试时，会显示为「**(未解決)**」和一个标记。

### 列表

- **日時** … 该尝试发生的时间。
- **結果** … 成功（绿色）还是失败（红色）。
- **アプリ** … Web（电脑）还是自助终端（共享平板）。
- **方式** … 用什么方式尝试登录（密码 / 单点登录 / QR 卡 + PIN 等）。
- **ユーザー** … 谁的尝试。如果用户名不存在，只显示「**未解決**」和标记（**输入的字符是有意不保存的**）。
- **理由** … 失败的原因（密码不一致、卡片无效、PIN 不一致等）。
- **IP** … 连接来源。
- **端末区分** … 上面说明的自动判定。
- **端末** … 共享平板显示设备名，电脑显示「Chrome / Windows 11」这样的标记。

## 查找与筛选

用上方的筛选可以缩小查看范围。

1. **期間（期间）** … 24 小时 / 7 天 / 30 天 / 90 天 / 全部。初始为 7 天。
2. **結果（结果）** … 可以只看失败或只看成功。调查时先选「失敗」会更容易看。
3. **アプリ** … 可以只看 Web 或只看自助终端。
4. **端末区分** … 可以只看「未管理」等。
5. **搜索框（IP / CIDR）** … 可以直接输入 IP 地址，也可以**按范围一次指定**。例如输入 `192.168.50.0/24`，就会涵盖 `192.168.50.1` 到 `192.168.50.254`。
6. 要清除全部条件时，点击「**リセット**（重置）」。

## 查看单条记录

点击列表中的行，右侧会打开该条记录的详情。

- **注意すべき兆候（需要注意的迹象）** … 只有存在可疑之处时才会在最上方以橙色显示。例如「自动操作标志被置位（可能是程序而非人）」「设备时钟偏差很大」。
- **日時・方式・理由・ユーザー** … 与列表相同的内容。
- **送信元 IP** 和 **プロキシチェーン** … 连接来源以及到达前经过的路径。
- **判定理由** … 判定设备类别的依据（`wrapper:device-owner`、`cidr:inside` 等）。保持英文，供系统管理员追查原因时使用。
- **端末シグネチャ** … 由浏览器特征生成的标记。与同一个人的其他记录对比，可作为「是否平时那台电脑」的参考。
- **収集シグネチャ** … 作为判断材料的信息一览。平时不需要查看。

> 💡 打开详情这个操作本身会记录到[操作历史](/manual/zh/operations/system/activity-log/user)（为了留下谁查看了内容的记录）。只浏览列表不会被记录。

## 不会被记录的内容

出于安全考虑，有些信息是**有意不保存的**。

- **密码和 PIN** … 完全不保存。
- **不存在的用户名** … 输入的字符不保存（因为可能混入打错的密码）。只保留一个标记，用于判断是否同一对象反复尝试。
- **QR 卡的内容** … 读取到的值不保存。只保留**种类**：是卡片的 QR 还是作业指示书的 QR。

## 输入项目

登录历史是**只查看记录的画面**。没有需要输入的项目，只需选择筛选条件。

| 筛选 | 会改变什么 |
|------|-----------|
| [期间](#field-days) | 查看多少天的记录 |
| [结果](#field-outcome) | 只看成功或只看失败 |
| [应用](#field-app) | 只看 Web 或只看自助终端 |
| [设备类别](#field-ownership) | 按是否公司设备筛选 |
| [IP / CIDR](#field-ip) | 按连接来源筛选（可指定范围） |

### 期间 [#field-days]

查看多少天的记录。初始为 7 天。查找较早的记录时请调大。

### 结果 [#field-outcome]

只看成功或只看失败。调查时先选失败会更容易看。

### 应用 [#field-app]

按来自电脑（Web）还是现场共享平板（自助终端）筛选。

### 设备类别 [#field-ownership]

按是否公司设备的自动判定筛选。各级别的含义和确定程度请参考「设备类别」一节。

### IP / CIDR [#field-ip]

按连接来源筛选。可以指定单个地址如 `192.168.50.10`，也可以**按范围**指定如 `192.168.50.0/24`。

## 常见问题

**Q. 失败突然增多了，该怎么办？**
A. 把「結果」设为失败，查看上方的「失败较多的 IP」「失败较多的对象」。如果是同一个人反复出现，请确认是否只是本人打错。如果出现没有印象的连接来源，请与系统管理员联系。

**Q. 用户栏显示「未解決」，是谁？**
A. 这是用不存在的用户名尝试登录的记录。输入的字符是**有意不保存的**。如果旁边的标记相同，说明反复使用了同样的字符。

**Q. 设备签名显示「—」，是异常吗？**
A. 不是异常。在不经过登录画面的路径（例如从外部认证画面直接返回）不会采集。

**Q. 明明是自己的工作电脑，却显示「未管理」。**
A. 「未管理」的意思是「没有属于公司设备的证据」，并不是断定为私人设备。从公司外部或其他网络连接时就会这样显示。

**Q. 我想知道有人登录之后做了什么。**
A. 这个画面只能看到登录本身。之后的操作请在[操作历史](/manual/zh/operations/system/activity-log/user)（`SY07`）中查询。

**Q. 我只想看共享平板的记录。**
A. 把「アプリ」筛选为自助终端。想只看某一台时，[设备管理](/manual/zh/operations/system/kiosk-device/user)（`SY09`）的设备详情中有「认证错误」列表。

**Q. 较早的记录查不到。**
A. 记录会自动删除（成功 180 天 / 失败 400 天）。需要调查更早的内容时，请与系统管理员联系。
