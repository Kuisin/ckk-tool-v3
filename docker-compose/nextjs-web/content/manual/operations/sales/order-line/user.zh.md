订单请书确定后，其中的每一行明细都会变成一条 **订单明细**。本应用把这些订单明细跨订单请书汇总到一起，用来跟踪 **库存预留、生产和发货进行到哪一步**。操作代码是 `SA05`。

> ⚠️ 本应用仍在试用阶段，画面和步骤今后可能会变。

## 本应用能做什么

- 把所有订单请书中已确定的订单明细 **汇总在一个列表** 中查看。
- 逐条确认指示书、发货和预留的进度。
- 查询可用库存并进行 **预留**。
- 订单取消时，作废该条明细。

**本应用不能新建或修改订单明细。** 新建和修改都在 [订单请书](/manual/zh/operations/sales/order-acceptance/user) 画面进行。原因请看下面的「[需要修改内容时](#需要修改内容时)」。

## 本页用到的术语

- **订单请书** … 从客户处接到的一笔订单的记录。
- **订单明细** … 订单请书中的一行明细。「哪个产品、多少支」这一行，就是生产和发货的依据。
- **受订确定** … 把已审批的订单请书确定下来、给明细编号的操作。
- **子号** … `ORD-202608-00012-01` 末尾的 `-01`。表示这是订单请书中的第几行。
- **预留** … 为这笔订单把库存留出来，防止被其他订单占用。
- **批次号** … 生产单位的流水号（例如 `#9001`）。创建指示书时自动编号（与指示书的单据编号 `WOR-…` 是不同的编号）。

## 编号的读法

订单明细的编号 = 订单请书的编号 + 子号。

```
ORD-202608-00012-01
└──────┬──────┘ └┬┘
   订单请书编号    子号（第几行）
```

同一张订单请书生成的明细，前半部分相同，只有子号不同。三行的订单会得到 `-01`、`-02`、`-03`。

**相同产品分成两行时也不会合并。** 客户订单上分成两行，订单明细就保持两条。反过来，也不能把一行拆成两条。**订单的一行 = 一条订单明细**，这一点始终不变。

## 画面的看法

打开应用后，会显示已确定的订单明细列表。

- **订单明细编号** … 上面说明的 `ORD-…-NN` 编号。
- **客户** … 从订单请书继承而来。
- **产品 / 数量 / 单价 / 金额** … 订单的内容。
- **交期** … 与客户约定的日期。
- **状态** … 用彩色徽章显示当前进度。

尚未确定的明细不会出现在这里，因为还没有编号。要查看这些明细，请打开 [订单请书](/manual/zh/operations/sales/order-acceptance/user)。

### 状态的含义

| 状态 | 含义 |
| --- | --- |
| 已确定 | 受订已确定，接下来进入生产和发货。 |
| 生产中 | 指示书已审批，工厂已开始生产。 |
| 部分发货 | 订购数量中只发出了一部分。 |
| 已发货 | 订购数量已全部发出。 |
| 已取消 | 已作废的订单明细。 |

## 详情画面能做什么

在列表中选择一行，即可打开该订单明细的详情。

### 查询库存并预留

点击「**库存核对**」，系统会查询该产品的库存，并 **把可用的部分预留** 下来。

- 预留的部分不会被其他订单占用。
- 不足的部分会显示为「缺口」。缺口通过创建 [指示书](/manual/zh/operations/production/work-order/user) 来生产。
- 库存核对只能在 **生产开始之前** 进行。生产开始后，数量由指示书一侧管理。

### 查看生产进度

「指示书」标签页会列出分配给该订单明细的指示书。**一条订单明细可以创建任意多张指示书**（分为库存分和生产分、先只做一部分之后再补做剩余等）。反过来，**同一产品的多条订单明细也可以合并到 1 张指示书（1 个批次）来制造**。「割当数量」（分配数量）是为该明细制造的根数，「予定数量」（计划数量）是那张指示书整体制造的根数（可能因不良备用量而更多）。

### 查看发货进度

「发货」标签页会列出包含该订单明细的发货书。这里显示的数量 **只是该订单明细的部分**。因为一张发货书可以同时装载多条订单明细，所以可能与发货书的合计数量不同。

随着发货推进，状态会自动变为「部分发货」→「已发货」。**不能发出超过订购数量的货。** 一旦超出，发货操作会被中止，并显示是哪条订单明细超出了。

### 取消

订单取消时点击「取消」。同时会自动执行以下处理：

- 已预留的库存 **全部释放**。
- 尚未完成的指示书会 **连带取消**（已完成的保持不变）。不过，**同时为其他订单明细生产的指示书（合并批次）不会被取消**，会保持原样。

已发货的订单明细，以及已经取消过的订单明细，不能取消。

## 需要修改内容时

**确定之后的订单明细，数量、单价、产品都不能更改。** 订单明细记录的是「与客户约定的内容」，如果事后可以改写，生产和开票所依据的数字就无从查证了。

在尚未确定（订单请书仍为草稿）期间，可以在 [订单请书](/manual/zh/operations/sales/order-acceptance/user) 的明细中随意修改。请把确定理解为 **决定「不再修改」的操作**。

如果确定后内容发生了变化，请与负责人商量。

## 遇到问题时

**列表里找不到**

可能尚未确定。请打开 [订单请书](/manual/zh/operations/sales/order-acceptance/user)，确认状态是否为「已确定」。如果审批和确定还没做，请先完成这些步骤。

**无法点击库存核对**

该订单明细已经开始生产。请到 [指示书](/manual/zh/operations/production/work-order/user) 一侧确认数量。

**发货时提示「将超过受订数量」**

该订单明细已发货的数量加上本次数量，超过了订购数量。请减少发货书的数量，或确认所选的订单明细是否正确。

**启动器里没有这个应用**

需要与订单请书相同的权限（`order_acceptance`）。看不到时请联系管理员。
